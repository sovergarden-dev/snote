What the fallback means

The side panel waits for a valid syrin:ready handshake from the app. Each load attempt can wait up to 12 seconds; if the handshake does not arrive, the panel retries once with a cache-busting URL. If the second attempt also has no valid handshake, the fallback screen appears. The app may have loaded even when the side panel did not receive the handshake.

A protocol-mismatch banner means the app and extension reported incompatible handshake versions. Otherwise, use the network state and retry count below to distinguish a browser-offline state from a load or handshake timeout.

Read the network state

offline
The browser reports that it is offline. Reconnect, then choose Retry.
online-unverified
The browser does not report itself offline. This does not prove that the app is reachable: the extension does not probe the app origin.
Retry count
Shows whether the automatic retry ran before the fallback appeared.

Copy or download diagnostics

  1. Open Diagnostics on the fallback screen.
  2. Choose Copy diagnostics or Download diagnostics JSON.
  3. Review the bundle before sharing it with the person helping you.

The bundle is sanitized and checked against its schema before it is copied or downloaded. It records handshake and load status, retry count, a message timeline, and optional device-local telemetry. It does not include note contents, note slugs, capability tokens, sessions, URL paths, raw build identifiers, or email addresses. Diagnostics are never uploaded automatically; sharing is your choice.

About CSP

In this extension version, cspFrameAncestors.reason = "not-inspected". The extension does not inspect CSP across origins, so this field does not say whether the host header is correct or incorrect.

If you maintain the app deployment and embedding still fails, ask its operator to verify that the response includes Content-Security-Policy: frame-ancestors 'self' chrome-extension://*. That check belongs to the host deployment, not to the extension’s cross-origin diagnostics.

What to try next

  1. If the browser reports offline, reconnect and press Retry.
  2. Choose Open in new tab to check whether the app works outside the side panel.
  3. If the fallback returns, copy or download diagnostics and share them only after reviewing the contents.

This guide is included in the extension package and opens locally from the fallback screen.
